# Security Policy

## Supported Versions

This repository is a documentation-only System Design Interview Guide. There are no running services, dependencies, or compiled artifacts to patch. The following documentation versions are maintained with corrections and updates:

| Version | Supported |
|---------|-----------|
| main    | :white_check_mark: |

## Reporting a Vulnerability

If you believe a contribution to this repository contains a security concern (for example, a diagram or snippet that inadvertently exposes credentials, internal endpoints, or sensitive architecture details), please:

1. **Do not open a public issue.**
2. Contact the repository maintainer directly through GitHub, or open a private security advisory if available.
3. Include a description of the issue, where it appears, and a suggested correction.

We will acknowledge receipt within 3 business days and aim to resolve or remove the content within 7 business days.

## General Guidance for Contributors

- Never commit passwords, API keys, tokens, or private configuration.
- If a case study references a real-world system, use only publicly available information.
- Do not include internal hostnames, IPs, or credentials in examples.
- Treat all contributed content as public; assume anything in this repository can be read by anyone.

## Disclosure Policy

Once a report is validated, we will:

- Remove or correct the affected content.
- Credit the reporter (if they wish to be credited) in the release notes or commit message.
- Publish a brief summary if the issue was public before being reported.
